Small-Scale Clinical Programming Pilot

A fixed-price pilot for one specified clinical-programming workflow in the client’s approved environment.

What the client buys: 12 named programming units in one workflow, each delivered against agreed specifications, checks, and review steps. The client chooses the unit type before the pilot begins.

Clinical programming work units

The client selects one unit type for the pilot; each unit is completed from approved input to documented disposition.
  1. SDTM Domain Unit: one named mapped domain, metadata, agreed checks, and QC evidence.
  2. ADaM Dataset Unit: one named analysis dataset, approved derivations, traceability, and QC per the client-approved plan.
  3. TLF Unit: one named table, listing, or figure against an approved shell and SAP.
  4. Conformance-Check Unit: one agreed set of client-approved checks against one frozen artifact, with finding triage and documented disposition.

A Standard Unit requires frozen input data and specifications, one named output, one standards library, agreed acceptance tests, and one correction/rerun cycle. Cross-domain dependencies, integrated summaries, protocol amendments, repeated data cuts, additional reruns, complex derivations, submission documentation, and lock-readiness work are separately scoped.

Patient-level data: the operating boundary

Use the existing client environment

  • Client-approved workspace, named access, blinding controls, and existing retention/audit controls.
  • One specifically approved model endpoint and feature set; no consumer tools or unmanaged data copies.
  • No new enterprise platform, live-system integration, or broad deployment during the pilot.

Data and regulatory classification

Before processing subject-level data, the client classifies it and documents the permitted use. HIPAA applies only where PHI/ePHI is handled by a covered entity or business associate; required BAAs and subcontractor agreements apply only where those roles exist. Client approval or hosting alone is not sufficient.
